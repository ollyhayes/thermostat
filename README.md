# Thermostat

A home heating monitor that runs on a Raspberry Pi. It reads a set of DS18B20 temperature sensors (and a pump on/off sensor) every second, stores the readings in SQLite, and serves a live, zoomable chart in the browser.

## Features

- **Live readings.** New values are pushed to the browser over a WebSocket as they're recorded.
- **Smooth zooming over years of data.** The chart (D3) shows per-second, per-minute or per-hour averages depending on how far you've zoomed out. Data is requested in time-based "chunks" and cached in the browser, so panning only fetches what's missing.
- **Compact storage and transfer.** Temperatures are stored as small integers (the sensors' 1/16 °C resolution). The data can be sent as a packed binary format instead of JSON. The `encoding-test/` folder holds the benchmark that compared the two.
- **Mock mode.** Generates fake sensor data, so the whole app can be run without a Pi.
- **Maintenance page.** A small React dashboard that shows connected sensors with their current readings, and the history of backup runs.
- **Backups.** The "grabber" runs nightly on another machine. It pulls any new readings from the Pi's HTTP API into its own copy of the database.

## How it fits together

```
 DS18B20 sensors ─┐
 pump sensor ─────┤   thermometer-reader      (RxJS: read every 1s, average per minute / per hour)
                  ▼
               SQLite  ◄──── grabber          (nightly cron on another machine, copies new data)
                  │
                  ▼
           web-interface/private               (Koa HTTP API + WebSocket chunk streaming)
                  │
                  ▼
           web-interface/public                (D3 chart, client-side chunk cache, React legend)

           maintenance/                        (separate Koa server + React dashboard)
```

| Folder | What it does |
| --- | --- |
| `thermometer-reader/` | Polls the 1-Wire sensors and GPIO pump sensor, and averages readings into precision levels |
| `common/` | Database access layer, logging and the config template |
| `web-interface/` | The main chart: server (`private/`) and browser code (`public/`) |
| `maintenance/` | Admin dashboard for sensors and backups |
| `grabber/` | Nightly replication of the Pi's data to a backup machine |
| `app.js` | Starts everything in one process |

## Running it

The build uses Webpack 4, which is why the build scripts pass `--openssl-legacy-provider`.

```bash
npm install          # also creates common/config.json from the template
npm run build        # bundle the chart frontend
npm run build-maintenance
npm start            # chart on http://localhost:8080, maintenance on :8081
```

The config template has `"mock": true`, so this runs on any machine with fake sensor data. On a Pi, set `mock` to `false` and list your sensors' serials (from `/sys/bus/w1/devices/`) in `common/config.json`.

Tests (Jest) cover the averaging pipeline and the client-side chunk store:

```bash
npm test
```
